# doc_common

Rust crates shared by DocHelper's per-format engines (`flutter_text_core`,
`flutter_sheet_core`, and the word and slide engines). Written from
scratch; the only dependencies are `flate2` for deflate streams and
`thiserror`.

| Crate | What it does |
| --- | --- |
| `doc_zip` | ZIP read/write for OOXML, ODF and EPUB packages: ZIP64, data descriptors, CP437/UTF-8 names, size limits, raw copying of unchanged entries |
| `doc_xml` | Pull reader, round-tripping element tree, escaping writer, namespace identities (Strict = Transitional OOXML), OOXML `_xHHHH_` strings; never expands DTD entities |
| `doc_encoding` | UTF-8/16/32 and 32 single-byte code pages, with detection; tables generated by `tools/gen_tables.py` |
| `doc_opc` | Document packages (OOXML and ODF): parts, relationships, content types; saving copies every untouched part raw and keeps ODF's `mimetype` first |
| `doc_ffi` | The Rust FFI plumbing every engine uses (`extern "C"` exports for `dart:ffi`; no C code): error codes, panic guards, string/buffer ownership, session handles, atomic file writes |
| `doc_image` | Picture kinds and sizes; PNG (every colour type, Adam7), GIF (first frame) and BMP decoded; JPEG headers for passthrough |
| `doc_font` | TrueType/OpenType faces (and collections): metrics, character maps, widths, `kern` and GPOS pair kerning, subsetting for embedding; `FontBook` indexes font folders by their headers, resolves families with Office substitutes (Calibri to Carlito...) and finds fallbacks for characters a face lacks |
| `doc_pdf` | A PDF writer: pages of paths, solid and gradient fills, pictures (JPEG passed through, others Flate with soft masks), text in Type 0 font subsets with ToUnicode maps, links; origin at the top left |
| `doc_layout` | Paragraph layout: faces with fallback per character, kerning, line breaking (spaces, hyphens, ideographs, long words), tabs, list labels, alignment and justification, line spacing (font metrics or PowerPoint's 1.2 em); drawn into `doc_pdf` pages |
| `doc_cfb` | OLE2 compound files (the container of `.doc`, `.xls`, `.ppt` and WPS binaries): sector chains, the directory tree, the mini stream; every chain checked for loops and bounds |
| `doc_art` | OfficeArt drawing records inside those files: record walking, shape properties and colours, and stored pictures turned back into PNG, JPEG, BMP, TIFF, EMF and WMF files |
